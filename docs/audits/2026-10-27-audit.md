## Data-integrity notes for long-term analysis

- **Double counting.** `Main` equals Mains_A + Mains_B (+C). Circuits are sub-meters
  of the mains, and `Balance` is mains minus circuits. Whole-home totals must use
  `Main` (or the legs when Main is absent, as in CSV exports) and never add
  circuits. `META_CHANNELS` and `get_monthly_costs` already do this. `/log` did not
  (#11, fixed).
- **`mains_intervals` and `readings`** hold the same Main energy from two sources: the
  UTC 1-minute chart backfill and the local-stamp live poll. No query adds them
  together. Keep it that way.
- **Units.** Poll and CSV-kWh rows are kWh per interval, CSV kWatts rows are converted
  using the interval, and watts = kWh × 60,000 only for 1-minute rows. Hourly
  compacted rows must not be fed to the watts helpers.
- **Timestamps.** `readings` uses the naive local wall clock of the recorded
  reporting zone. `mains_intervals` and climate use UTC. `energy_hourly` follows
  `readings` (local hour starts). The fall-back DST hour merges two clock hours.
- **Durable history.** Live minute rows older than `DB_RETENTION_DAYS` (365) were
  deleted, so no long-term per-circuit record survived. The new `energy_hourly`
  table keeps per-channel hourly kWh, observed seconds and sample counts
  indefinitely (`ENERGY_HOURLY_RETENTION_DAYS=0`). It is filled every poll, after
  CSV imports, and by a one-time backfill at poller start.

## Deployment

This PR adds a table (created by `ensure_table()` on start) and a one-time backfill.
It does not change any service unit or environment file. It would be deployed with
the existing release procedure in `docs/COLLECTOR_MIGRATION.md`: new release
directory, locked runtime, restart the guest units. That deployment was **not**
performed. New optional variables: `LOG_LEVEL`, `LOG_LEVELS`, `LOG_FORMAT` and
`ENERGY_HOURLY_RETENTION_DAYS`.
